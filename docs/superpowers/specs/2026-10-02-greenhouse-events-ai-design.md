# 大棚模拟、决策助手与知识依据统一改进设计

状态：2026-10-02用户回复“可以”，统一方案已批准，进入实施。参考审查见[论文与项目审查](../../research/2026-10-02-agent-greenhouse-reference-review.md)。实施步骤见[实施计划](../plans/2026-10-02-greenhouse-ai-integration.md)。

## 目标

把现有M3时序生长参考、在线株高纠偏、环境预警与三维温室结合为一个演示工作区。运行中自动出现暴雨、降温等模拟事件，由现有DeepSeek服务生成可执行的仿真设备方案；设备动作改变模拟环境，再观察风险是否缓解。决策助手能读取并参与同一次模拟，以自然语言回应问题、按需调用资料和工具；回答正文、引用与执行结果分别清晰呈现。模型机制及新增知识均保留论文或机构资料出处、单位与适用条件。

用户明确要求自动随机事件与AI解决。自动处置范围为本地仿真设备。数据文件、真实设备与现有聊天工具权限沿用已有约定。

## 项目现状

- M3LiveService保存独立运行、半小时时钟、已消费M3数据、株高滤波和风险；当前M3环境直接进入模型，没有事件或设备响应。
- digitalTwin/index.vue把株高、LAI和环境交给scene.applyState；M3路径里的设备开关目前全部为false。
- Three.js场景已有屋窗、侧窗、风机、遮阳、补光、灌溉与加热动画，以及OperatingFlows气流/水流/热流示意，可复用。
- TomatoSimulationEngine已有温湿交换、设备响应、加热、光照和土壤代理计算；设备出力及天气系数为未校准假设。
- DeepSeekService已有结构化规划调用；现有聊天编排以查询/草稿为主，未连接M3运行的自动设备处置。
- AgentOrchestrator把知识库关键词命中作为一般回答的前提，检索降级会直接拒答，回答被固定结构和声明限制；通用回答分支未统一保存会话历史。
- AgentChatRequest的旧数字runId未传入编排，当前M3 UUID也未连接聊天工具；新增明确的运行上下文，兼容旧接口。
- 本次读取的知识索引有480块、480向量、35来源，包含环境与水肥等资料。问题同时存在于检索使用方式和具体主题覆盖。
- 用户补充六篇论文已有摘要来源；本轮增强条件与主题组织，并补充经核对的天气、温湿机制与模型方法资料。

## 三种实现方式

1. **随机事件自动处置，保留手动触发（推荐）**：完整展示发现、判断、执行、反馈。随机种子可重放；可手动选择事件供答辩展示。
2. **仅手动选择事件**：更容易控制演示顺序，缺少自动随机过程。
3. **只展示天气动画与AI建议**：改动较少，但设备不会改变模型结果，不能形成用户要求的处置循环。

采用方案1。单一大棚工作区通过自动事件、自动处置两个开关控制运行，不新增几套互斥的展示模式。

## 运行流程

开始推演 → 接收M3参考记录 → 事件发生 → 环境响应与风险检测 → AI读取当前状态 → 校验仿真设备动作 → 执行动画与环境计算 → 观察反馈 → 必要时调整 → 恢复或显示未解决。

数据与模型由服务端推进，浏览器只显示结果并请求下一步。所有面板、设备动画、风险、时钟与事件记录绑定同一个runId。

### M3参考与事件计算

M3原始环境、测量和既有误差评价保持来源完整。新增scenario字段记录受事件和设备影响的虚拟环境、生长参考、风险与动作；每项标为模拟。

M3株高继续校正参考模型。事件场景以校正后的参考状态作为背景，积累受扰动环境造成的生长变化，展示假设事件对生长的影响。事件场景值不与M3实测计算预测精度，也不把随机风雨伪装成M3记录。

事件先改变环境边界，再经连续温湿交换和设备响应影响棚内。更新按半小时数据时间，温度、湿度和光照采用有上下限的渐进变化。大棚封闭时，室外暴雨不直接当作棚内降水或土壤灌溉。株高、叶面积和干重变化采用模型步长，设备开启不立即宣称生长恢复。

M3为棚内环境参考，不当作室外实测。首期以M3逐时变化构成未扰动基线，叠加有状态的事件异常与设备响应；需要外界边界时由配置提供估计代理并标明来源。温度异常按交换速率积累/恢复；水汽异常用绝对湿度或水汽压推进，再结合温度计算RH和VPD，避免只降低RH数字却不改变水汽。模型至少考虑补光/日积分、CO₂与通风的关联，蒸发降温效果受空气湿度限制，冷湿天气处理需要排湿与保温配合。结构热容量、换气率、设备出力未标定时保存为工程假设，不能标注为完整GreenLight实现。

保留一条同事件、同初态、未干预的影子计算供处理前后对照，标签为模型推演；不是现场因果验证。已发布的参考历史帧不回写。

### 自动随机事件

- 暴雨：雨势、云量、室外湿度上升，光照下降，伴随有限降温与风。
- 骤降温：外界温度逐步下降，触发保温/加热需求。
- 热浪：温度上升，触发遮阳、通风或蒸发降温需求。
- 强风：风力与阵风示意，模拟屋窗/侧窗动作约束。
- 连续阴雨：持续弱光与偏湿环境，观察补光和湿度管理。
- 夜间高湿：高湿持续暴露、低VPD提示，观察环流与温湿调整。
- 设备故障：模拟单台设备不能响应，AI需调整方案或报告需人工处理。

事件生成使用每次运行保存的随机种子；首个事件在2个模拟小时后出现，天气结束后随机等待4–12个模拟小时，最多同时一个天气事件与一个设备故障。强度、持续时间、初态和结束时间均进入日志。默认参数如下，均为演示假设，保存到配置并显示；温度与湿度偏移作用于天气边界，经模型交换影响棚内。

| 事件 | 随机强度范围 | 持续时间 |
| --- | --- | --- |
| 暴雨 | 雨势20–50mm/h；温度偏移−3至−6°C；湿度边界90–98%；光照倍率0.2–0.5；风6–12m/s | 2–6h |
| 骤降温 | 温度偏移−6至−10°C | 3–8h |
| 热浪 | 温度偏移+5至+9°C；白天光照倍率1.0–1.15 | 4–10h |
| 强风 | 风速12–20m/s；温度偏移−1至−3°C | 2–4h |
| 连续阴雨 | 雨势2–8mm/h；光照倍率0.15–0.4；湿度边界85–95% | 8–16h |
| 夜间高湿 | 湿度边界90–98%，仅夜间生成 | 4–8h |
| 设备故障 | 随机选加热/排风/灌溉一台不能响应；自动发生概率为一次天气事件的10%，同时最多一台 | 保持至用户模拟恢复设备 |

天气强度在首尾各一个半小时时段渐入/渐出。光照扰动仍遵守昼夜，夜间不会凭空产生太阳光。风只用作本次场景的风雨动画和通风约束，来源为随机模拟。结束窗口到达时天气终止，剩余风险继续按状态计时。手动触发服从同一活动事件数量限制，允许明确结束当前天气；结束天气不等于风险解除。

默认推进半小时/秒。AI请求期间显示“分析中”，暂停后续模型时钟推进，天气和设备画面保持当前状态，避免事件在决策返回前结束。用户暂停时不产生新事件。

### AI处置与反馈

复用现有DeepSeek后端服务，新增面向本次仿真的决策上下文，包含当前事件、棚内外环境、风险/暴露、作物状态、设备健康、当前开关、可用动作、此前动作与反馈。

输出结构化方案：情况判断、处置理由、设备目标、持续步数、预期改善项和下一次检查条件。设备词表沿用AgentDeviceCodes。服务端检查动作字段、设备健康、数值范围和互锁后，写入本次运行并驱动下一步仿真。

事件发生后请求一次；执行至少两个半小时时段再反馈，确需调整才再次请求。每事件最多三次模型决策，一次只允许一个请求；返回时校验runId、事件和状态版本，过期决策记为未应用。

AI请求失败、解析失败或动作被拦截时，如实显示原因。启用已有规则的应急托底时单独标为“规则托底”，记录与AI方案的区别。不能返回硬编码回答并标为已调用AI。

解除取决于环境和连续风险计时；事件自然结束、风险缓解、设备动作已执行分别记录。未恢复时继续观察或显示未解决，不固定几秒后强制成功。设备故障需要维修的结论保留为人工检查任务，仿真不伪造维修成功。

## 决策助手连接同一模拟

### 上下文与工具

- 聊天请求新增明确的simulationRunId字符串与上下文类型，保留旧Long runId兼容。前端从当前运行选择或大棚入口携带UUID，显示正在关联的年份、数据时间与事件。
- 服务端读取实际存在的运行，绑定到本轮工具上下文；模型不能靠自由文本runId切换运行。每轮读取新快照，会话历史不能替代当前环境。
- 可调用工具：当前运行快照、风险与事件、设备健康及可用动作、近期动作和反馈、知识检索、仿真方案校验/执行。现有病害与平台查询工具继续用于相关问题。
- 大棚自动处置与聊天用同一个决策/校验/执行服务，避免产生两个互相覆盖的控制者。每次动作携带状态版本和请求标识，重复请求不重复执行，过期返回不应用。
- 用户问原因或询问建议时回答并给方案；明确要求执行仿真动作，或自动事件处置开启时，才应用设备动作。普通聊天不能因提到设备便自动更改开关。
- 自动处置与聊天的控制请求共享运行级串行与事件预算；新动作覆盖目标时记录原因，所有面板更新到同一状态。运行过期、不存在或已结束时提示重开/重新关联，不伪造当前状态。

### 自主回答与准确性

大模型负责组织回答，知识库是按需使用的能力。删除一般回答依赖知识库词条命中的条件；检索为空或不可用时，仍可回答一般概念、推理与项目说明，并简短说明无法核实的部分。

按问题需要选择工具：

1. 日常交流、已知概念和一般解释可直接回答，不强制检索。
2. 当前大棚状态、为何报警、动作效果先读当前运行，再决定是否需要知识依据。
3. 论文结论、具体阈值、量化农事处方与防治建议按需检索。若信息缺失，仅对无法确定的结论说明不足；已有可用信息仍给出解释和下一步检查。
4. 多步骤处置按状态→方案→执行→反馈循环。实现借鉴ReAct、Adaptive-RAG等方法，不宣称训练或复现这些研究系统。

引用必须与实际取得的资料对应，不编造论文、编号、实测值或已执行动作。涉及不确定光照换算、未测风速、果实和叶面湿润时保留假设/缺测标识。药剂具体用量仍须登记、资料及使用条件；该约束不变成所有日常问题的固定尾注。模型返回不能自行修改计算参数或风险阈值。

一般回答和有引用回答统一保存会话历史。网络/模型错误、检索无结果、运行失效分别表示，不能一概包装成资料不足。取消字面横幅与每题固定标题要求；来源类型以结构化元数据呈现，确需说明时自然写入正文。

正文可以有结论、解释、列表或表格，结构由问题决定。先直接回应用户关注点，必要时展开证据和行动；允许简短追问，但已有信息足够时先给可用建议。展示简短判断依据和可观察工具记录，不展示隐藏推理链。

### 回答协议与界面

回答保留自由Markdown正文，附加独立元数据：当前运行/时间、使用的来源、假设或缺测、仿真方案、动作状态和反馈。自然正文不承担设备执行字段的解析职责，动作使用结构化协议并由服务端校验。

决策助手采用桌面宽屏布局：主区为会话，侧区展示当前关联大棚及当前轮来源/动作。空状态先说明可以问什么，保留少量贴近当前场景的示例。聊天与大棚中的AI面板复用正文和执行卡。

- 正文支持段落、标题、列表、强调、表格与引用。使用转义文本节点和受控解析，不注入任意HTML。
- 回复与进度分开：短提示显示正在读取大棚/查资料/生成方案，详细工具过程默认折叠；工具名称转为用户可读名称。
- 引用按每条回复保存和定位；点击正文引用打开该回复的来源，不跳到其他轮的同号引用。来源含标题、作者/机构、日期、适用条件和链接；未使用的检索候选不展示为引用。
- 动作卡显示建议、待执行、已执行、被约束拦截、观察中、已缓解或未解决；实际状态来自服务端。
- 提供停止本轮回复、复制、重试等必要操作。停止生成不撤销已执行动作；运行中断保留已有记录，重试不重复执行设备动作。
- 延续暖白与农业绿配色，文字层级、宽度和密度服务于长答案阅读；不默认堆满统计卡或每题添加药剂声明。

## 论文依据与知识补全

### 模型依据

观测到达后的株高更新延续既有EKF，参考Oliveira等观测同化研究检查状态/观测口径；三维形态参考Smoleňová等FSP研究。环境响应参考GreenLight及WUR多传感器控制研究，控制目标参考牛通等环境计分思路。先形成可解释、可记录的简化动态关系，参数不足的部分不假装完成完整机理模型校准。

建立参数登记：名称、单位、来源类型、出处、适用条件、当前值与上下界。观测数据、论文/标准数值和工程假设区分记录。研究中环境计分不是产量，风险分数不是发病概率；设备处理效果以模型输出和暴露时长显示，论文实验效果不记作本项目效果。

### 新增与整理内容

优先补齐：异常天气的温室应对；冷湿环境中的排湿/保温与结露；湿帘效率与高湿限制；补光和CO₂条件；模型修正与反馈控制的解释。先使用已收录标准和六篇用户论文的相关条目，新增农业农村部天气指导、大学推广机制及经核对论文摘要。地域、棚型、品种、生育期、单位、发表时间与限制条件随摘要保留。

新来源遵循现有知识摘要schema，注册读取器、按来源分组入库、产生向量并重载检索；文献库同步显示可引用状态。本地论文已存在的来源不重复建立；需要补充主题或条件时更新原来源摘要。来源冲突保留条件，不简单平均阈值；索引不可用如实显示，不能只增加PDF文件便宣称知识接入完成。

## 页面与三维

大棚作为主体，延续目前的暖白、农业绿风格。左侧为当前模拟环境、作物与风险；右侧为活动事件和AI处置；底部为事件/动作时间线及温湿变化小图。

主要操作：开始/暂停、推进速度、自动事件、自动处置、手动触发、重新开始、查看M3来源。事件触发弹出简短说明；AI区依次显示发现、分析、动作、反馈与结果。

雨滴位于室外并尊重棚体；天空、光照和雾感随事件变化。强风驱动风向示意与植株摆动，加热、补光、环流、滴灌和通风沿用设备动画。动画读取模拟状态，风雨为示意而非实测。天气效果采用批量绘制，并随现有画质档位降低粒子数量，离开页面释放资源。

- 后端m3/scenario事件引擎：随机调度、事件状态、虚拟环境与作物响应、影子计算。

- 后端m3/scenario动作校验：设备词表、健康与互锁、执行/拦截记录。

- digitalTwin事件面板：控制、AI解释与动作反馈；scene.ts及独立天气效果模块：天气和设备动画。
- AgentChatRequest/Controller及AgentOrchestrator：运行上下文、按需检索、完整会话历史、自然回答与执行反馈。
- 工具注册、GuardrailService和返回DTO：仿真作用域、动态状态/引用检查、独立回答与动作协议。
- agentChat页面及共享回答组件：可安全显示的Markdown、逐回复来源、折叠过程、动作卡和流式状态。
- CitedKnowledgeReader与知识摘要清单、文献库来源：条件整理、新来源登记、入库和索引实际状态。
