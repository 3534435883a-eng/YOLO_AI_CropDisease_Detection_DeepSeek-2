# Horti-M3 番茄模型实测验证设计（历史提案）

## 状态

历史提案。后续用户明确要求将范围扩大为全农业平台适配；本文件仅保留此前“独立验证”的边界记录。现行设计见 `2026-09-29-horti-m3-platform-adaptation-design.md`。

## 背景

项目当前有两类温室模拟：15 分钟 AgentRun 与日级策略评测；另有农情输入后的方案推演。后端番茄作物模型按温度、CO₂、根区水分和 PPFD 推进 LAI、株高与各器官干重。日级模拟使用固定情景，不读取公开历史观测。现有 `agent_parameter_source` 能记录参数出处和核实状态，但它不是实测样本库。

Horti-M3-Tomato 提供 2023–2025 三季番茄温室资料，包括每 30 分钟环境观测、定期株体/生理测量、物候、产量和部分农事记录；来源说明与下载入口见[论文](https://www.nature.com/articles/s41597-026-07074-w)和[数据 DOI](https://doi.org/10.5281/zenodo.17217565)。GreenLight 是用于园艺温室及作物的动态模型平台，作为模块组织与温室—作物关系参考，不直接引入其代码；见[官方仓库](https://github.com/davkat1/GreenLight)。

Horti-M3 的品种、栽培处理、温室和根区条件不等同于项目虚拟的 8 号温室，因此它适合做独立验证数据，不能直接当作项目现场数据或未经验证的模型参数真值。

## 目标与非目标

### 目标

1. 让用户选取本地 Horti-M3 非图像数据，保留年份、品种、处理、来源与观测时间等元数据。
2. 用观测到的环境时序驱动项目番茄生长子模型，并将模拟输出与同批次作物观测对齐比较。
3. 展示字段映射、缺失/重复/单位问题、观测与模拟曲线及误差指标。
4. 将 Horti-M3 数据集与 GreenLight 模型平台加入现有“知识库来源”登记，不增添第三个文献页签。
5. 清楚区分公开观测、模拟输出与单位转换假设；验证完成前不修改模型参数。

### 非目标

- 不把 Horti-M3 观测写入既有 8 号温室 AgentRun、设备状态或旧业务数据库。
- 不把当前结果描述为项目现场验证、正式校准或产量承诺。
- 不在首版自动寻优或覆盖 `TomatoGrowthParameters`，不训练视觉病害模型。
- 不导入公开数据集中的植物图像；首版只处理温室时序、表型、物候、产量和必要的管理元数据。
- 不复制/打包 GreenLight 源码或增加运行时依赖。

## 用户流程

1. 用户进入“温室推演 → 模型验证”。
2. 用户从 Horti-M3 数据 DOI 下载并解压所需年份/种植周期的非图像资料，再选择环境工作簿、表型/物候/产量文件。数据只保存在应用配置的外部资料目录或本次临时会话中；不得写入 Git 仓库。
3. 页面读取文件前进行结构检查，识别年份、周期、品种、施肥处理、日期、时间戳、单位和植株编号；用户确认字段匹配后运行校验。
4. 页面以原始环境观测作为输入，按数据本身的 30 分钟时间点推进作物生长模型；不插值出“新实测值”。若未来选用其他采样频率，需保留实际时间戳并显式说明聚合/插值方法。
5. 页面将 LAI、株高及可确认口径的生物量/产量/物候观测与模拟输出对齐，显示观测曲线、模拟曲线、样本数、缺失率、MAE、RMSE 和平均偏差。样本不足或单位基准不匹配时不计算该项并显示原因。
6. 用户可查看完整来源、字段转换方式、未纳入指标及模型版本，并导出本次对照摘要。

## 数据映射与边界

| Horti-M3 观测 | 项目字段/用途 | 规则 |
|---|---|---|
| Air Temperature (°C) | `SimulationState.temperatureC` | 原值输入；缺失点不伪造 |
| Relative Humidity (%) | `airHumidityPct` / VPD 派生 | 原值输入；VPD 由项目公式计算并标为派生量 |
| CO₂ (ppm) | `co2Ppm` | 原值输入 |
| Soil Moisture (%) | `soilMoisturePct` | 保存原值，并显示数据集测量口径；不改称土壤体积含水率以外的单位 |
| Light Intensity (lux) | PPFD 驱动 | 保留 lux 原值；如转换成 PPFD，必须使用显式、可查看的转换假设和来源标记。结果须提示光谱差异带来的不确定性 |
| LAI、Plant Height、LDW 等 | 模拟作物观测对照 | 运行前核对取样方法、单位、聚合层级和面积/植株基准；口径不一致则排除该指标，不猜测换算 |
| 物候、产量、管理记录 | 阶段/终局辅助核对 | 只使用数据集实际覆盖的记录；缺少的病虫害、施肥、灌溉信息显示为缺项，不用模拟值补成观测 |

模型输入的观测字段仍标为 `PUBLIC_DATASET`（仅限验证工作区）；该标签不加入 AgentRun 既有来源枚举，也不让外部数据触发设备动作。

## 页面布局

- 顶部：标题、数据集来源卡、适用范围声明和当前数据集/模拟模型版本。
- 左侧：数据导入、年份/周期/品种/处理选择、字段映射确认、运行检查结果。
- 主区：观测与模拟曲线、误差摘要、字段级比较表、来源/换算说明。
- 空状态：提供 DOI 与接收格式说明；不展示伪造的 Horti-M3 样例曲线。
- 错误状态：指出文件、工作表、字段、时间戳、单位或样本对齐的具体错误；跳过未识别列并要求用户确认，不按列位置猜测。

## 技术设计方向

- 新建独立验证服务/结果类型，复用纯函数 `TomatoCropGrowthModel`；环境输入直接构造为观测驱动状态，不经过 `TomatoSimulationEngine.advance`，从而不把 Horti-M3 的棚内历史观测误说成模型生成值，也不把观测重播当作设备模型验证。
- 以文件导入契约隔离 Horti-M3 原始目录的跨年差异；每条记录保留数据源、批次元数据、时间、植株 ID 和原字段。支持原始 `.xlsx` 环境数据与 `.csv` 表型数据所需的解析能力在实施前检查依赖与具体文件结构。首版暂不承诺解析图片、Word 管理记录或整个压缩包。
- 模型参数采用当前登记版本并只读；导入或运行不调用参数刷新、更新 SQL 参数行或变更仿真常量。
- 在“知识库来源”目录增加 Horti-M3（公开数据集）和 GreenLight（软件/模型平台）的来源记录，展示来源类型与公开链接；不把“来源已登记”说成“模型参数已核实”。
- 若实现需要新增数据库表，使用 create-only 独立迁移；如果仅需会话临时数据，则优先不持久化原始观测。

## 验收标准

1. 不上传 Horti-M3 文件时页面是明确空状态，不回退成“实测数据”样例。
2. 选择一个真实数据子集后，可以识别数据批次信息、时间序列和字段/单位，并在用户确认前不启动验证。
3. 模拟输入保留观测来源，所有转换和派生字段均能查看；观测值不进入模拟输出字段。
4. 观测与模拟只有在时间、单位及基准匹配后才对齐；不匹配时显示排除理由。
5. 输出至少包含曲线、样本数、缺失率、MAE、RMSE、平均偏差和模型/参数版本。
6. 验证操作不会写 AgentRun 表、修改 8 号温室运行状态、刷新/改写现有模型参数或触发任何设备动作。
7. 来源目录保留已批准的“两标签”结构，加入来源条目但不增加页签。

## 待实施前确认

- 需用一个真实 Horti-M3 子集核对工作簿、工作表、列名和元数据结构；论文给出的模式不足以保证所有年份/周期文件完全同构。
- lux 到 PPFD 的映射与 LDW 的面积基准/测量口径需基于原始文件和可引用说明确认。无法核实的指标必须从误差统计中排除。
- 原始文件可能很大；首版不复制全库进 Git，导入容量、临时存储与清理策略需由实施计划明确。

## 自审

- 范围清楚地把实测验证与模型参数拟合分开，避免“参考了公开论文”被误读为“已校准”。
- Horti-M3 不完全适配项目环境，设计用元数据选择和不匹配排除规则处理，不默认跨品种/处理硬比。
- 没有新增参考文献页签，保留此前获批的两标签文献目录。
- 最关键的实施前依赖是实际数据文件结构和 lux/LDW 口径；计划应先用小型真实样本做只读结构核验，再确定文件解析器。
