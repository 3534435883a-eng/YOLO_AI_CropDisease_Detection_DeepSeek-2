# 文献与来源资料库设计

## 目标

在“知识与数据”工作区增加一个“文献与来源”入口，方便演示和答辩时查阅仓库中的本地 PDF，并核对 AI 决策助手可引用的登记来源。

## 已确认的范围

- 将“文献与来源”作为“知识与数据”下的一个新页面，不增加两个独立侧栏入口。
- 页面使用两个标签：“本地文献”和“知识库来源”。
- 本地文献目录展示项目内现有的 71 份 PDF，覆盖 6 篇研究论文、番茄相关标准以及其他作物标准；按资料类别筛选并支持按标题/文件名搜索。
- 用户可从页面在浏览器中打开 PDF 原文件。PDF 不复制到前端构建包，不上传文件，也不自动将全文导入 RAG。
- 知识库来源标签展示当前已登记的来源元数据，而不生成助手过往的实际引用历史。页面需说明：来源已登记不代表某次回答实际引用了它；某篇本地 PDF 也不因此自动成为可检索知识。
- 决策助手每轮实际采用的证据继续以该轮对话中的引用为准。

## 页面结构

页面沿用现有知识页面的暖纸白、深木棕和低饱和橄榄绿视觉体系，以桌面宽屏为主要展示尺寸。

页面标题为“文献与来源”，副标题说明本地存档与知识库登记来源的区别。标题区可显示本地 PDF 数量和已登记来源数量；数字只从成功加载的数据计算。

“本地文献”标签包含：

- 研究论文、设施番茄标准、其他作物标准的类别筛选和结果数量。
- 按文件标题搜索。
- 紧凑表格展示文件名、资料类别、来源文件夹和文件大小。
- “打开 PDF”操作在新标签页中通过本地后端读取原文件。
- 文件目录缺失、加载失败、没有匹配项时分别显示清楚的状态。

“知识库来源”标签包含：

- 按名称、类型或版本搜索。
- 展示来源名称、类型、权威等级、版本、许可说明和原文链接（字段存在时）。
- 在列表顶部固定显示来源边界说明，避免用户把登记目录误认为特定回答的历史引用清单。
- 后端不可用或没有登记来源时提供独立的错误和空状态。

## 数据与接口

### 本地 PDF

新增只读知识资料接口：

- `GET /api/ai/knowledge/library` 返回文档 ID、显示文件名、资料类别、文件夹标签与文件大小。接口不向前端暴露操作系统绝对路径。
- `GET /api/ai/knowledge/library/{id}/content` 按目录接口返回的稳定 ID，以 `application/pdf` 和 inline disposition 流式返回对应文件。
- 文档根目录由 Spring Boot 配置项指定；本地默认配置指向仓库内的 `农业论文` 目录。目录缺失时接口返回明确的不可用状态，不返回伪造条目。
- 服务器只读取 PDF。文档 ID 必须映射到目录内的已发现文件；解析后的真实路径必须仍处在配置根目录中；只允许 PDF 扩展名，拒绝目录穿越和任意文件读取。

资料类别根据仓库既有文件夹和文件清单确定，不从标题推测作者、期刊、年份等不存在的书目信息。

### 知识库来源

新增轻量只读接口 `GET /api/ai/knowledge/sources`，读取现有 `KnowledgeSourceRepository`，返回来源代码、来源名称、来源类型、权威等级、版本、原文链接和许可说明。该接口不重载索引、不执行重新 ingest，也不探测向量服务。

不新增数据库表，不增加引用历史写入。页面文案称此列表为“知识库已登记来源”，不得称为“最近已引用来源”或“本次回答引用”。

## 导航与路由

- 新页面路由为 `/referenceLibrary`，标题“文献与来源”。
- 将新路由添加到现有 `knowledgeWorkspace` 分组，在病害知识库和视觉—知识覆盖之后。
- 其他菜单、页面 URL、RAG 索引和助手引用数据结构保持不变。

## 错误处理与边界

- 本地文献接口和知识来源接口分别加载，某一类服务不可用时另一标签仍可使用。
- PDF 被移走或读取失败时，显示文件无法打开的提示，不把服务器路径展示给用户。
- 服务端不接受上传、删除或任意路径参数，不向浏览器传送 PDF 全集；只有用户打开单份文件时才流式传输该 PDF。
- 任何本地 PDF 都不得被标成“已入知识库”，除非现有知识来源登记与索引状态确实能证明这一点；本页 V1 不计算全文入库状态。

## 验收标准

1. “知识与数据”下出现唯一的新入口“文献与来源”，可直接访问 `/referenceLibrary`。
2. 本地文献列表能展示仓库已有 PDF，能按类别筛选和搜索；点击任一条目只读取并打开对应 PDF。
3. 页面不将系统绝对路径发给客户端；非法 ID、越界路径和非 PDF 文件无法被读取。
4. 知识库来源列表展示登记元数据与原文链接，并明确说明登记来源不等于某次回答的实际引用。
5. 现有“视觉—知识覆盖”页、决策助手的逐轮引用、知识库索引和已有路由继续工作。
6. 页面遵循已批准的桌面端视觉体系，在常见桌面窗口中易读；窄屏下筛选与表格仍可操作。

## 暂不包含

- 上传、编辑、删除本地文献。
- 将 PDF 自动解析或导入向量知识库。
- 持久化助手逐轮引用历史、最近引用统计或文献使用分析。
- 推断 PDF 的 DOI、期刊、作者、发表年份或版权许可。
