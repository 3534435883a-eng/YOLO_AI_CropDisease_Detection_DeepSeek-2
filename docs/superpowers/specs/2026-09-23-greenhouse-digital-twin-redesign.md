# 双跨温室数字孪生重做设计（2026-09-23）

## 目标与边界

重做比赛演示中的单座双跨薄膜番茄温室，使使用者能在**同一个连续的三维场景**中把相机自由移动到棚内外任意观察位置，并从该处任意调整朝向。模型需同时呈现写实的外围结构、棚内作物环境、完整的执行设备与感知传感器；设备状态与项目的农业自动控制业务流程一致。

本阶段为标注来源的数字仿真，不宣称有实物一比一测绘、施工图合规认证或真实设备接入。现有 26 m × 13 m、四条种植床和 104 株番茄是可调整的演示基线，不是现场实测。先交付可靠的三维模型、自由漫游和确定性控制仿真；模型验收之后再接 AI 识别、解释和 Agent 展示。

## 实现路线

比较三条路线：

1. 全部用 Three.js 原语和程序化贴图：最容易参数化，但设备近景细节、薄膜和作物质感难达目标。
2. 下载现成整座温室模型：初看精细，但结构与设备布局不匹配，授权、资产体积和后续状态联动难控。
3. **选用混合路线**：棚型、桁架、种植行、路由和设备挂点参数化；对关键近景设备使用经过许可、可追溯的 glTF/GLB 资产或自行建模；统一 PBR 材质、光照与质量档位。

保持 Vue 3 + Three.js 0.186 的现有技术栈，不为了场景引入另一套前端框架。参考 Three.js 官方相机、材质与 glTF 文档；候选辅助为 `donmccurdy/glTF-Transform`（资产检查和压缩）与经过审阅的 Three.js 技能说明。`ahujasid/blender-mcp` 只在确认本机 Blender 可用且确有高质量定制资产需求时采用；不把它作为交付前提。社区技能示例若与 Three.js 0.186 冲突，一律以官方文档和实际构建为准。已有本地 `context-optimization` 技能仅用于工作过程的上下文整理，不压缩模型质量或项目内容。

## 场景和设备

场景按“外部场地 → 棚体外壳 → 内部作物与道路 → 供水/供电/供气 → 执行设备 → 传感器/标注”分层，但始终是**一个可连续漫游的场景**。棚体呈现双跨拱架、中央天沟、檩条、立柱、端墙、门、薄膜、卷膜/屋顶通风结构及连接件；内部有四条种植床、作物冠层、中央通道和服务通道。尺寸集中配置，不把几何坐标散落在组件中。

设备布局遵循演示用的工程逻辑：

- 滴灌：室外或端部水源/过滤泵阀组 → 主管/分区支管 → 各床滴灌带 → 根区湿度传感器；显示阀门、流量与水量状态。
- 补光：沿冠层上方布置灯列及布线，状态改变灯体发光和冠层照度显示。
- 屋顶/侧部通风窗、端部排风机与 HAF 环流风机分别建模；环流与换气不是同一执行器。
- 遮阳：位于棚内屋脊/冠层上方的幕布与导轨，开合量连续变化。
- CO₂：供气源/控制阀和分配管路分离呈现，供气状态与通风/强排风互锁。
- 湿帘降温：进风端湿帘及供水循环与对端排风机协同，状态可独立观察，降温耗水单独记录。
- 感知：室外气象、棚内多点冠层温湿度/CO₂/光照、根区湿度与水路流量等分区布置；避免在进排风口或灯具旁把局部读数误称整体环境。

每个设备都有稳定 `deviceCode`、所属分区、模型挂点、状态映射和点击检查信息。模型表现是物理设备工作状态的结果，不以整棚泛光取代执行器。参数属于仿真设计而非工程验收值。

## 相机与交互

相机是自由移动能力，不是 A/B/C 固定视角，也不依赖预设机位。主模式为自由飞行：W/A/S/D 前后左右、Q/E 下降/上升、鼠标调整朝向、Shift 加速、Esc 退出指针锁定；可从棚外连续飞到内部，在近景、屋脊、冠层与设备之间任意探索。辅以鼠标环绕、平移和缩放，便于整体观察；两模式切换应保留当前相机位置和朝向。演示快捷机位只做“传送到附近”，随即仍可自由移动。

自由飞行不以棚膜或碰撞边界限制相机可达位置；为避免穿模影响观感，可给地面与设备设置轻量近距提示，必要时另设有碰撞约束的行走模式，但不得取代无限制的自由飞行。UI 明示操作方法，失焦时停止移动，切换/卸载时解除指针锁并清理监听。完整、透明、隐藏或局部剖切仅是外壳显示选项，**不改变相机自由度**。点击设备弹出状态、传感器读数、控制来源与最近动作；HUD 可隐藏以提供纯场景演示。

## 视觉和性能

统一米制尺度、PBR 金属/粗糙度与真实透明/透光参数；薄膜、镀锌钢、潮湿土壤、水、塑料管、叶片和果实使用不同材质响应。环境光照、太阳方向与昼夜变化配合柔和阴影、色调映射；近景关键物件优先细节，重复构件/作物使用实例化或分级细节。经许可的模型记录来源和许可证；必要时用 glTF Transform 优化纹理与网格。避免未经证明的“照片级”承诺：以关键机位视觉审查、材质一致性、浏览器实际帧率和可调低/中/高画质为验收依据，低画质也保留全部设备功能。

## 数据、控制与阶段划分

现有 `digitalTwin/index.vue` 读取日级 `/eval/{batchId}/series`，`scene.ts` 只表达五类布尔执行状态并使用受限的 `OrbitControls`；因此需重新拆分场景几何、材质、相机、设备动画、状态适配和 HUD，避免继续把全部逻辑堆在一个场景文件中。

**阶段 A——模型与漫游**：完成结构、植株、全部设备和传感器、PBR、摄像机自由飞行、点击检查、材质显示模式和场景性能基线。可用明确标注的本地演示状态驱动设备动画，暂不做 AI 接入。

**阶段 B——确定性仿真**：以已有 `/agent/runs` 的 15 分钟运行节拍为场景时间轴。扩展后端设备代码、状态转移、传感器模拟、水/电/CO₂ 耗用、湿帘与排风协作、CO₂ 和换气互锁，并提供按运行 ID 读取历史快照的接口；前端只渲染已保存的状态或明确标注的本地演示状态。手动、自动、锁定、故障和资源不足各有可解释的视觉反馈。后端缺失时可以展示演示模式，但不得伪装在线真实数据。原日级策略/产量评测保留独立分析入口，不能映射成 15 分钟实时设备状态。

**阶段 C——AI（A/B 验收后）**：将既有视觉识别证据、RAG/解释和 Agent 决策挂到已完成的设备与快照标识上；规则引擎继续负责执行约束，AI 不直接越权下发硬件命令。比赛“一键演示”和自由手动探索共享同一场景与数据契约。

## 验收与测试

1. 从棚外任意方位到棚内各通道、冠层、屋顶和设备近景均可连续自由飞行并任意转向；没有强制预设机位、自动旋转夺回控制、输入失焦后继续漂移的问题。
2. 灌溉、补光、屋顶/侧部通风、遮阳、HAF 环流、CO₂、湿帘和排风等各自可定位、检查且状态有对应动画；室内外与根区传感器能显示来源、数值和单位。
3. 设备布局与水路、风路、气路对得上；CO₂/强排风等互锁、湿帘/排风联动和故障/手动锁定可通过确定性重复运行验证。
4. 白天、夜间、薄膜完整/透明/剖切及内外关键机位人工检查视觉质量；前端构建、后端相关测试与资源释放检查通过，浏览器至少在目标演示机上完成画质档位与帧率实测。
5. 所有仿真指标明确标记 `SIMULATED` 或相应来源，原病害识别和既有业务接口不被破坏。

## 暂不纳入

无真实硬件连接、真实施工尺寸/规范认证、离线电影级路径追踪、由 AI 自动执行农药处理或替代已有后端安全互锁的功能。
