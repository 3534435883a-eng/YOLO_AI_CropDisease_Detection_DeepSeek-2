# 大棚场景农艺参数审计与验证

日期：2026-10-08。范围：`ScenarioAgronomyModel`、`ScenarioSession`及对应独立测试；不修改M3原始观测、株高校准、任务存储或AI生成逻辑。

## 1. 审计结论

本次先修复数值与执行一致性，再说明参数证据层级。设备功率、流量、储水层厚度、基质阈值和气候增益保留为工程假设，未把文献中其他棚型、土壤或设备的数据直接替换为本项目实测。

已修复：

- 水量更新在每次调用内部按1模拟分钟积分，避免“一个30分钟段先注入全部水量再排水”与30个1分钟段产生不同结果。每段资源仍汇总整个调用时段，M3输入仍为30分钟一次，未增加测量频率。
- 冠层、根区和病害条件暴露按1分钟段末状态累计。在段内环境保持恒定的计算假设下，阈值跨越的时间离散误差限于一个积分分钟，避免段末首次变湿就计入整个30分钟；原始观测仍只有30分钟间隔。
- 根区含水降至萎蔫代理或更低时，水分生长因子降到0，取消“完全缺水仍保留15%生长”的下限。土面蒸发代理仍单独保留并受可用总水量约束，不生成负水量。
- 已运行设备在强风事件、故障、动作到期和温度更新后复核互锁。排风停止后湿帘停止；强风关闭屋窗和侧窗；新状态达到29°C后停止下一时段加热；通风时停止CO₂。保护是离散虚拟规则，不是实际硬件安全认证。
- 持续步数要求整数，2.5步不能静默截断成2步。
- 恢复农艺存档时同时核对水量守恒、设备累计时长、电量、滴灌量、湿帘水量和CO₂账本，拒绝异常资源或暴露时长。

响应版本为 `m3-scenario-agronomy-20261008-v4`，农艺版本为 `root-water-condition-proxy-20261008-v2`。旧机制的存档拒绝恢复，防止新旧算法混合产生比较结果；既有M3观测不变。

## 2. 权威资料支持到哪一步

| 对象 | 本次核查 | 项目处理 |
|---|---|---|
| 空气VPD | 饱和水汽压公式及相对湿度定义支持由即时温度、RH计算VPD | 使用kPa，温度用°C、RH用百分数；不把瞬时计算说成日平均参考蒸散 |
| 根区储水 | 储水由体积含水率和有效层体积计算；可用水取决于田间持水量、萎蔫点和根层 | 252m²×0.25m×1000=63000L；0.25m明确称虚拟有效储水层，不是番茄最大根深 |
| 蒸散胁迫 | 根区水分胁迫应影响蒸腾分量，而不是把土面蒸发全部乘同一胁迫 | 保留25%土面蒸发代理、75%胁迫调制分量；份额和线性蒸散系数仍未标定 |
| 灰霉条件 | 温室番茄灰霉与凉爽、高湿及持续湿叶相关 | 15–25°C、湿润代理≥0.55、连续6h设置复查提醒；代理和预警级别不是感染概率 |
| 叶斑类条件 | 早疫病等叶斑病与适温、湿叶或高湿相关；病原、生育期和地区不同 | 20–30°C、连续4h仅为项目的工程复查窗口，不能称全部叶斑病的感染阈值 |
| M3几何 | 原论文给出14个处理小区与每小区18m² | 252m²作为虚拟资源账本的全部试验区规模，不等于CK单处理面积或整栋温室面积 |

VPD采用 `es(T)=0.6108×exp(17.27T/(T+237.3))`，`VPD=es(T)×(1−RH/100)`。FAO给出水汽压与湿度关系，但并未提供本项目的ET线性系数。[FAO-56第3章](https://www.fao.org/4/X0490E/x0490e07.htm)

FAO给出根区可用水与有效深度的关系、土壤蒸发和作物蒸腾的区分，并列出番茄最大有效根深参考0.7–1.5m。该范围不能代替基质槽、浅层湿润或本项目虚拟储水层的实测；项目0.25m只保留为明确假设。[FAO-56第8章](https://www.fao.org/4/x0490e/x0490e0e.htm)

明尼苏达大学番茄灰霉资料描述约15.6–23.9°C、高湿和5–8h湿叶条件。本项目取近似温区与6h观察窗口，仍缺真实叶湿、病原、品种和症状进展验证。[UMN：Gray mold of tomatoes](https://extension.umn.edu/agriculture/specialty-crops/vegetable-farming/disease-management/gray-mold-of-tomatoes)

同校早疫病资料支持温湿条件的重要性，并说明适温范围、病原和传播条件。当前“叶斑类”是笼统的人工复查提示，4h数值没有来源证明为统一感染阈值。[UMN：Early blight in tomato and potato](https://extension.umn.edu/agriculture/specialty-crops/vegetable-farming/disease-management/early-blight-in-tomato-and-potato)

M3原论文的14小区、18m²小区与棚内环境监测设计作为几何及数据来源；这些事实不证明本项目滴灌、储水层或设备热效率已标定。[Gong等：Horti-M3-Tomato数据论文](https://www.nature.com/articles/s41597-026-07074-w)

## 3. 核心参数与量纲

| 参数 | 当前值 | 解释和后续标定对象 |
|---|---|---|
| 有效种植参考面积 | 252m² | 全部试验小区面积；虚拟场景规模 |
| 有效储水层 | 0.25m | 假设；需槽体截面、湿润体积和根系分布 |
| 初始含水率、田间持水量、饱和 | 30、34、46%vol | 假设；需基质持水曲线与传感器标定 |
| 缺水关注、萎蔫代理、过湿关注 | 24、12、36%vol | 假设；不是通用番茄灌溉指令 |
| 排水时间常数 | 120min | 假设；需进水/排水量曲线 |
| 滴灌、湿帘水流 | 15、2L/min满出力 | 设备规模假设；水量=流量×出力×模拟分钟 |
| CO₂质量流量 | 0.025kg/min满出力 | 假设；与ppm响应尚无完整气体质量守恒模型 |
| 潜在ET代理 | `clip(0.25+3.4×PPFD/800+0.7×VPD,0.1,7)`mm/day | 即时输入的日尺度速率代理，不是FAO Penman–Monteith |
| 胁迫调制后ET | 潜在ET×`(0.25+0.75×Ks)` | 25/75分量为假设；1mm×1m²=1L，分钟/1440换算 |
| 干旱因子 | `clip((theta−0.12)/(0.24−0.12),0,1)` | theta≤12%vol时为0，停止水分生长贡献；两个含水界限仍待标定 |
| 根区连续异常复查 | 120min | 工程窗口；观察水分而非宣称已发生根病 |
| 冠层湿润代理 | 湿润系数0.0015/min/RH点；RH起点82%；阈值0.55 | 无量纲代理，不是叶湿传感器 |
| 冠层干燥代理 | `0.002+0.006×VPD+0.012×环流出力`/min | 未标定，环流不凭空修改棚均RH或生成风速场 |
| 加热高温保护、窗强风保护 | 29°C、10m/s | 虚拟工程保护，29°C并非作物通用温度极限 |
| 动作步长及期限 | 30min/步，2–24整数步 | 即1–12h虚拟动作；现场需要短周期反馈、限幅与实际控制器 |

功率假设（kW满出力）：加热40、滴灌0.30、侧窗0.05、补光12、遮阳0.02、CO₂阀0.05、屋窗0.03、排风1.20、湿帘0.75、环流0.30。电量=`功率×出力×分钟/60`；没有设备铭牌和电表证据时不根据文献随意修改。

气候半小时响应保持原假设：加热1.8°C、湿帘最大2.0°C、辐射差1.2°C/800PPFD，空气交换0.14加通风0.35，水汽交换0.12加通风0.32，通风干空气代理1.6g/m³，湿帘增湿0.8g/m³，CO₂增量100ppm，CO₂交换0.12加通风0.5，遮光0.55，补光150μmol/m²/s，lux→PPFD系数0.0185。气候增益没有直接由电功率、热容和气体体积推导，因此目前只能解释为方向及组合响应代理。

API参数登记补充单位、适用范围、来源链接与引用所支持的对象。`admissibleMin/Max`指计算安全范围，不是推荐管理区间；`calibrated=false`保留。文献链接不能把工程数值升级成验证过的实测参数。

### 既有回归测试中的旧夹具

全量运行另发现四处旧测试失败，逐项核对后未用改真实参数的方式凑结果：

- `TomatoSimulationEngineTest`的两个用例仍硬编码四床142.8m²和旧26×13m棚体；改用当前M3面积、储水层和同一已说明的拱形体积近似，公式保持独立计算。
- `ResourceAccountingTest`把处方中的m³当作L，并把默认30分钟动作与15分钟定额直接比较；补充×1000单位换算和30/15时长换算，再额外检查15分钟动作恰好声明60L。规则、引擎和评测原有账本没有因此被改写。
- `ModelDiagnosticReportTest`原先用旧日期、15分钟、四床面积并硬断言历史结果；独立耦合循环改用当前profile、30分钟和252m²，补齐同一时段的能耗，并与本次平台P2结果逐项比较，允许误差仅为输出四位小数舍入。它验证两条执行路径一致，不验证田间准确性，也不把历史模拟值称为实测。

## 5. 面向答辩的准确表达

“历史观测回放不断校正生长状态；场景模型把同一事件下的方案转换为环境、根区水分、条件风险与资源变化，再与未干预分支比较。水量和资源账本、时长、互锁和状态恢复已经有独立验证入口。设备及病害条件模型仍属于可解释仿真；将来接入根区、叶湿和设备计量数据后，可继续标定相应响应参数。”

不能用株高预测校准误差证明设备响应或病害预测已经可靠；不能把条件风险降低说成病斑治愈；不能把模拟节水/增重改写成实际生产收益。

当前生长模块未显式计算维持呼吸、植株死亡或真实果实含水和饱满度；单果重量仍有GDD代理部分。极干测试仅验证取消虚假生长增量，并不验证干旱后的生理恢复、失叶或死亡过程。
