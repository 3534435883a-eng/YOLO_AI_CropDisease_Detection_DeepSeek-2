# 大棚中心流程整合交付说明

日期：2026-10-08。依据已确认的流程整合方案实施，项目名称保持不变，本轮未制作视频、未上传GitHub。

## 已实现的主线

```text
同一农情任务
  → 文字描述 / 病叶识别 / 农情CSV核对
  → 结合当前大棚、候选证据和来源的问答
  → 关联农事计划与人工行动
  → 明确点击评估并应用虚拟设备方案，或一键自动接管
  → 设备回执、环境与根区响应、资源代价、同事件未干预对照
  → 人工复查登记
  → 导出本任务报告
```

入口为 `/digitalTwin?mode=m3`。右侧四个标签承载助手、农情证据、行动与复查、事件；左侧展示关键环境、根区水量、处理差异和设备作用说明；中央保留原三维大棚与设备交互，底部显示流程和观测修正入口。独立问答继续保留，不自动读取大棚。

### 例：番茄连续阴雨、叶片有斑

1. 在大棚点击“开始接入”，输入问题；可在农情证据中上传病叶并识别，补充生育期、斑点位置和管理记录。
2. 助手读取该任务的证据和当前大棚状态；图像只作为候选，环境条件不能代替病因诊断。
3. 需要形成完整行动清单时打开关联农事计划。人工检查与处理事项保存在同一任务，返回大棚后可以继续登记。
4. 点击“评估并应用虚拟设备方案”。设备AI核对同一任务的病叶候选、人工复查、当前天气和根区，重新判断允许的动作；只有通过护栏并获得实际仿真回执才标为已应用。
5. 继续运行，观察温湿度、根区含水率、冠层湿润条件及用水用电变化。未干预分支接受相同的天气事件，以便说明组合方案带来的模拟差异。
6. 将实际看到的病叶或滴头变化填入“记录现场复查”。这些记录标为人工登记，可继续用于问答、计划、设备评估和报告。

“一键自动接管”保留随机天气/设备事件与AI自动处理，进入时直接打开事件面板，并明确绑定当前农情任务。后续自动事件沿用该任务最新证据和复查，任务编号随场景存档恢复。模型等待AI时暂停推进；三维画面和页面操作仍可使用。默认运行是仿真，不控制实物设备。

## 衔接和状态

| 项目 | 实现 |
|---|---|
| 统一编号 | 农情任务、M3运行、问答会话、请求分别编号；关联请求明确携带任务与运行 |
| 图片证据 | 当前识别及历史识别记录保存原图路径、标注图信息、类别候选、置信度、模型和阈值；其他作物保持独立 |
| CSV | 使用既有解析接口，核对字段、单位、未识别列及冲突后作为任务证据，不直接伪装成传感器接入 |
| 普通问答 | 没有任务/运行关联时不读取或操作大棚；关联会话按任务与运行隔离 |
| 规划 | 使用同一任务与当前运行，冻结本轮事实；不另开旧基线评测冒充处理效果 |
| 行动 | 人工完成登记与仿真回执分开；人工不能勾选出“已执行仿真” |
| 复查 | 原子追加、固定记录ID防重复，服务器登记北京时间与人工来源 |
| 报告 | 主文汇总问题、行动、对照、资源、作用代价、复查、证据与回答；冻结上下文/回执JSON作为附录 |
| 跨页 | 首页、环境、资源摘要、导航和关联入口沿用选中运行；离开大棚页面不暂停模型 |

## 新增计算机制

### 根区水分与虚拟生长

根区以升计算水量，按模拟分钟累积灌溉、蒸散、溢流和排水，再换算为体积含水率 `%vol`。设备健康和实际出力参与通量；缺水、过湿的持续暴露形成风险提示和虚拟生长的水分胁迫。恢复存档时检查水量守恒。

首期假设：总参考种植区252m²、根深0.25m、根区体积63000L，初始30%vol、田间持水量34%、饱和46%、缺水关注24%、过湿关注36%、萎蔫代理12%，排水时间常数120分钟，满出力滴灌15L/min。面积参考全部试验小区，不等同CK处理面积；其余参数为公开展示的工程假设，未完成现场标定。

蒸散使用瞬时光照/VPD代理，不能称为已标定的FAO-56模型。肥液EC、N/P/K吸收、基质分层及根系空间过程未进入本轮计算。

### 冠层湿润与病害条件

空气湿度、VPD和环流出力推动无量纲冠层湿润代理；凉湿/暖湿条件及持续暴露形成病害适生条件提示。环流不直接伪造棚均温、棚均湿或实测风速。不存在由检测置信度直接生成的病斑面积、病原量或治愈率。

### 作用、代价和对照

同一事件推进处理分支与未干预分支，展示温湿度、根区和虚拟生长差异。设备作用说明包含机制、组合方案当前差异、潜在代价和复查条件；组合差异不能归因为某个单独设备的因果效果。用水、用电和CO₂按实际仿真出力乘时长与假设容量计量，不冒充水表、电表或费用实测。

M3株高观测更新保持原有独立滤波与预测误差口径。虚拟干预不会改写历史测量，也不能用株高校准结果证明设备环境响应或防治效果已可靠。

## 连续运行与流畅性

- 单一服务端时钟每秒推进选中运行的1/12/48个半小时步长；手动步进与自动推进串行化，等待AI期间保持当前模型时刻。
- 前端使用共享store、一个只读轮询和增量历史接口；只请求本地连续帧之后的新帧，命令回执跳过游标时会补齐中间历史。
- 拒绝旧运行、旧游标、旧场景版本和早于新播放命令的响应；页面卸载只取消订阅。
- 已消费帧、滤波、作物、风险暴露、场景、设备时限、资源和显式随机状态保存到原子存档，每5秒或显式操作保存。恢复核对数据哈希、参数及模型版本，恢复为暂停；在途AI标为中断，避免重复应用。
- 存档失败会显示错误并停止自动推进；释放缓存前保留成功存档。新建前暂停旧运行。
- 保留一个三维场景及既有实例化渲染、设备动画、交互和质量控制，没有新增第二个重场景。修正路由入场后的场景高度测量及相机控制遮挡。

这些为已完成的机制改造，尚未测得端到端延迟、帧率提升或长时运行成功率，不能写成量化性能成果。

## 持久化位置和接口

- 农情任务：Spring Boot工作目录下 `data/farm-tasks`；可用 `agent.task.directory` 配置。文件限制2MB、每类记录最多200条，UUID路径限制和原子替换。
- 运行：M3导入目录下 `runtime/live-runs`；存档仅包括已消费历史与恢复所需状态。
- API：`/agent/tasks` 的创建/读取/更新、证据、问答、人工行动、复查和报告；`/m3/live/{id}/playback`；历史GET的 `afterCursor` 增量参数。
- 本轮复用已有应用认证。任务按UUID保存，没有新实现多用户任务所有权隔离；多人公开部署前需补所有权校验。
