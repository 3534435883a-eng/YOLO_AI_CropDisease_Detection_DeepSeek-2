# M3大棚、随机事件与决策助手实施结果

日期：2026-10-02。对应已批准的[统一设计](../superpowers/specs/2026-10-02-greenhouse-events-ai-design.md)和[实施计划](../superpowers/plans/2026-10-02-greenhouse-ai-integration.md)。本轮功能已实现，前后端生产构建及实际业务流程已完成。

## 1. 现在怎样运行

M3半小时记录到达 → 原有生长预测与株高观测修正 → 场景环境响应 → 风险累积 → DeepSeek读取当前事件、设备和知识 → 产生结构化仿真方案 → 校验后应用 → 后续时段计算 → 与同事件未干预对照比较 → 风险仍存在时继续调整。

- 同一运行UUID连接三维大棚、控制面板和聊天助手。模拟暂停时，页面仍能读到另一页面发起的AI动作。
- 自动事件包括暴雨、骤降温、热浪、强风、连续阴雨、夜间高湿和设备故障；也可手动触发、结束天气或恢复故障设备。
- 自动AI与显式聊天执行请求使用同一仿真服务；普通咨询不会改变设备。重新回答不重复提交设备动作。
- AI请求在后台运行，等待期间停止消费新的M3时段。每个事件最多三次自动决策；失败、动作阻断和风险未解决均如实记录。
- 执行后的最低观察期是两个半小时步长，即1小时；AI正文中的自由表述不改变这一程序条件。

## 2. 模型与动作

场景以M3棚内历史环境作基线，维护温度、水汽、CO₂、光照和事件偏移。加热降低相对湿度但不直接排走水汽；通风参考模拟外界边界，高湿限制湿帘蒸发能力；遮阳和补光影响光输入及热异常。设备存在目标出力、健康状态、有效期、版本和幂等校验。

强风关窗、通风与CO₂施用、湿帘与排风、湿帘与加热等约束在服务端校验。场景温度达到29°C时禁止新增加热目标，这是项目工程保护条件。整套方案通过检查后才应用，不能半套成功。

三维天气雨粒、风线、照明和设备动画读取同一场景状态，支持画质缩减、暂停及降低动态偏好。巡览和设备交互沿用既有大棚能力。

**适用边界：**15项响应参数标记为工程假设、未标定。随机天气、外界温湿边界和设备响应不是M3实测。根区水分未完成水量平衡，滴灌和循环风机目前主要用于动作展示；株高场景响应不是产量模型。模型版本为`m3-scenario-anomaly-20261002-v2`，不能称为完整GreenLight或所引用论文的复现。

原有M3观测修正与独立评估保持自己的数据来源和时序，随机事件场景不用于证明M3精度提升。

## 3. 助手与回答界面

- 普通问题允许大模型直接回答，按需要检索；移除所有回答必须带固定横幅和同一组标题的要求。
- 服务端读取并绑定当前运行，模型不能自行切换到另一运行。当前场景、M3历史环境、观测株高和模型结果保留不同来源。
- 工具结果进入模型上下文；成功回答统一保存历史，支持追问。只有真正使用且编号有效的来源进入最终引用列表。
- 正文使用安全节点渲染段落、列表、强调、表格、代码和引用；不注入任意HTML。工具过程默认折叠，来源可单独查看。
- 支持复制、停止、重新回答。停止会取消聊天生成与后续工具执行；已经提交的独立仿真AI任务不会被撤销。
- 模型仍可能冗长或在时间描述、适用条件上不够准确。界面的运行时钟、来源时间和结构化动作状态是核对依据；不能把自由回答当作保证正确的设备控制记录。
