# 回答政策：什么该答、什么不答（2026-09-27 变更）

> 本文记录**回答边界**本身——它是这套系统最像"产品立场"的东西，也是最容易被一次改动悄悄挪掉的。
> 起因：用户要求"放开部分提示词限制，让模型可以结合已学习的知识来回答"。

## 一、变更前后

| | 变更前 | 变更后 |
|---|---|---|
| 无检索依据时 | **一律拒答**（编排层根本不调作答步） | 视**是否命中过关键词**分流，见下 |
| 问题点名的病/虫库里没有 | `knowledge.search` 走**工具级终态**，直接终止本轮 | 不再终止；降为"低分 + 把缺什么说清楚" |
| 证据与问题主题不一致 | 只能答"依据不足" | 可另起一段补通用农艺知识，**须原样标注出处声明** |

## 二、分流规则（唯一的判据是关键词命中数）

```
检索命中数 == 0  → 离题（如"帮我写一首诗"）           → 拒答
检索命中数  > 0  → 问题落在农业域内、只是库里依据不足   → 通用知识作答（须带声明）
检索判据通过     → 有可靠证据                          → 常规带引用作答（不变）
```

选"命中数"而不是让模型自判是否该答，是因为它是**已有信号**、可复现、不引入额外一次模型调用。
实测"帮我写一首诗"命中数为 0，仍正确拒答。

## 三、放开的边界（放开的是"能不能答"，不是"能不能给量"）

1. **离题仍拒答**——命中数 0 即拒。
2. **无引用不得给药剂剂量**——护栏 `GuardrailService` 原有的 `PESTICIDE_KEYWORDS` 规则不动；
   剂量与安全间隔期只能由当地登记与产品标签决定。
3. **出处声明逐字校验**——通用知识回答的第一行必须是
   `【以下不来自本项目知识库，属通用农艺经验】`，编排层逐字检查，**没带就不放行**
   （宁可拒答，也不能让通用经验被读成知识库依据）。
4. **不得用名字相近的病害替代作答**——写进作答指令第 6 条。
5. **不声称已执行设备操作**——护栏原有规则不动。

## 四、为什么不能把"通用经验"混进引用里

知识库回答与通用经验回答在用户眼里长得一样，但**可信度来源完全不同**：
前者能追到编号与原文，后者是模型的记忆。混在一起，用户就无法判断哪句该去核对。
所以两者在三个地方被强制分开：回答正文里的声明段、终态原因码 `GENERAL_KNOWLEDGE`、
以及前端徽标「通用经验（未引用知识库）」。

## 五、一处被这次变更推翻的旧决定（值得记）

"未知病/虫→工具级终态"是 2026-09-27 早些时候为提升拒答准确率做的：它把难负样本拒答率
从 **16.7% 拉到 94.4%**。但同一天它就**成了本次放开的障碍**——实测「番茄脐腐病怎么防」
在那里被拦下，永远走不到通用知识作答那一步。

**同一个动作在一个指标上是收益，在另一个指标上就是障碍。** 处理方式是把它降级为
"低分 + 说明缺什么"，把"不许拿相近病害替代"这条意图**改写进作答指令**——
规则从"拦在门口"改成"写进要求并校验"。

> 副作用要如实说：这条终态去掉后，**难负样本拒答率这个数字的含义变了**——
> 原先那些被终止的提问现在会走通用知识作答（带声明）。该指标不能再单独引用，
> 需要同时报告"其中多少条转成了带声明的通用知识回答"。

## 六、终态与可观测性

- `GENERAL_KNOWLEDGE` 是**唯一**允许出现在 DONE 终态里的原因码。
  `finish` 原有的约定是"DONE 一律不带 reason"（避免成功回答挂着内部故障码），
  为它开了白名单——因为它是**回答性质**而非故障，必须同时进客户端与审计记录。
- 关键词命中数 `bm25HitCount` 已透传到 SSE 的 step 事件，接口层面即可判断分流依据。
