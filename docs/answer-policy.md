# 回答政策：什么该答、什么不答（2026-09-27 变更）

## 2026-10-09：大棚关联规划的当前边界

普通独立问答继续保留。关联任务的管理规划使用当前任务与同一运行，按请求天数输出管理清单，不使用旧标准场景评测作为该任务效果；以下是本轮新增的关联规划约束，后续章节保留历史政策背景。

- 用户记录、M3历史回放、事件仿真和未干预对照有不同来源和条件，数值不同不能直接判成同测点实测冲突。
- 图像只是候选；模拟SEEDLING/LAI等初始化状态不能用来判定现场摘叶量、坐果或产量。
- 工程4小时/6小时复查窗口不是感染阈值，不据此声称几天后必然发病。
- 未提供所需检测、面积与设备条件时，不凭记忆给出水肥绝对用量；改成每平方米也不能弥补依据不足。不自行扩展到请求天数之外。
- 档案中的旧AI回答和待处理MODEL_PLAN_PROPOSAL是未核验建议，不因为保存过就升级成资料依据。
- 新规划只生成待处理建议；设备执行、人工完成和复查分别依据实际回执或人工登记，干预差异允许不利，不承诺治愈。

这些是提示与归档边界，不能保证大模型每次生成完全正确；输出仍应结合本轮证据和实际农情复核。

> 本文记录**回答边界**本身——它是这套系统最像"产品立场"的东西，也是最容易被一次改动悄悄挪掉的。
> 起因：用户要求"放开部分提示词限制，让模型可以结合已学习的知识来回答"。

## 一、变更前后

| | 变更前 | 变更后 |
|---|---|---|
| 无检索依据时 | **一律拒答**（编排层根本不调作答步） | 视**是否命中过关键词**分流，见下 |
| 问题点名的病/虫库里没有 | `knowledge.search` 走**工具级终态**，直接终止本轮 | 不再终止；降为"低分 + 把缺什么说清楚" |
| 证据与问题主题不一致 | 只能答"依据不足" | 可另起一段补通用农艺知识，**须原样标注出处声明** |

## 二、分流规则（唯一的判据是关键词命中数）

```
检索命中数 == 0  → 离题（如"帮我写一首诗"）           → 拒答
检索命中数  > 0  → 问题落在农业域内、只是库里依据不足   → 通用知识作答（须带声明）
检索判据通过     → 有可靠证据                          → 常规带引用作答（不变）
```

选"命中数"而不是让模型自判是否该答，是因为它是**已有信号**、可复现、不引入额外一次模型调用。
实测"帮我写一首诗"命中数为 0，仍正确拒答。

## 三、放开的边界（放开的是"能不能答"，不是"能不能给量"）

1. **离题仍拒答**——命中数 0 即拒。
2. **无引用不得给药剂剂量**——护栏 `GuardrailService` 原有的 `PESTICIDE_KEYWORDS` 规则不动；
   剂量与安全间隔期只能由当地登记与产品标签决定。
3. **出处声明逐字校验**——通用知识回答的第一行必须是
   `【以下不来自本项目知识库，属通用农艺经验】`，编排层逐字检查，**没带就不放行**
   （宁可拒答，也不能让通用经验被读成知识库依据）。
4. **不得用名字相近的病害替代作答**——写进作答指令第 6 条。
5. **不声称已执行设备操作**——护栏原有规则不动。

## 四、为什么不能把"通用经验"混进引用里

知识库回答与通用经验回答在用户眼里长得一样，但**可信度来源完全不同**：
前者能追到编号与原文，后者是模型的记忆。混在一起，用户就无法判断哪句该去核对。
所以两者在三个地方被强制分开：回答正文里的声明段、终态原因码 `GENERAL_KNOWLEDGE`、
以及前端徽标「通用经验（未引用知识库）」。

## 五、一处被这次变更推翻的旧决定（值得记）

"未知病/虫→工具级终态"是 2026-09-27 早些时候为提升拒答准确率做的：它把难负样本拒答率
从 **16.7% 拉到 94.4%**。但同一天它就**成了本次放开的障碍**——实测「番茄脐腐病怎么防」
在那里被拦下，永远走不到通用知识作答那一步。

**同一个动作在一个指标上是收益，在另一个指标上就是障碍。** 处理方式是把它降级为
"低分 + 说明缺什么"，把"不许拿相近病害替代"这条意图**改写进作答指令**——
规则从"拦在门口"改成"写进要求并校验"。

> 副作用要如实说：这条终态去掉后，**难负样本拒答率这个数字的含义变了**——
> 原先那些被终止的提问现在会走通用知识作答（带声明）。该指标不能再单独引用，
> 需要同时报告"其中多少条转成了带声明的通用知识回答"。

## 六、终态与可观测性

- `GENERAL_KNOWLEDGE` 是**唯一**允许出现在 DONE 终态里的原因码。
  `finish` 原有的约定是"DONE 一律不带 reason"（避免成功回答挂着内部故障码），
  为它开了白名单——因为它是**回答性质**而非故障，必须同时进客户端与审计记录。
- 关键词命中数 `bm25HitCount` 已透传到 SSE 的 step 事件，接口层面即可判断分流依据。

## 七、推演通道：第二条政策（2026-09-28 新增）

前六节讲的是**一条**通道的政策：`/ai/agent/chat`，它检索、带引用、按证据决定答不答。
新增的 **农事规划推演**（`/ai/agri/plan/*`）是**另一条通道，政策不同**：它不检索、不强制引用、
不因缺依据拒答，让模型用自己的知识针对用户棚况做条件推演。

### 为什么不能合成一条

用户的要求是"松开限制，让模型用自己的知识推演"。而现有编排器的三道闸门与之逐条冲突：
无可靠证据即拒答（`AgentOrchestrator` 的 `NO_RELIABLE_EVIDENCE` 分支）、回答必须含有效引用编号
（`CitationReferenceValidator`）、越权与药剂护栏（`GuardrailService`）。

用 `mode` 开关塞进同一个编排器看起来省事，实则会让两条政策的护栏逻辑互相缠绕——
而严格通道那边刚调好（难负样本拒答率 16.7% → 94.4%），动它是净损失。
因此推演**独立成链路**，`AgentOrchestrator` 一行未改。

代价要如实说：**不检索、不强制引用，意味着这条通道没有可核对的出处。**

### 推演通道的边界（放开的是"能不能答"，不是"能不能乱说"）

1. **首行强制推演声明**：`【以下为模型推演，非实测、非知识库依据，请结合当地实际复核】`。
   与严格通道的区别在处置——严格通道逐字校验、没带就拒答；这里**服务端补齐**（记 `bannerInjected`）。
   理由：推演通道里模型没有任何知识库内容可混入，"忘了写声明"不等于内容有问题。
2. **数据缺失时明说，不替用户假定**。未提供的字段随提示词一并交给模型，也在界面上高亮。
3. **药剂剂量默认关闭**：`agent.plan.allow-pesticide-dosage=false` 时不得给出具体农药的
   商品用量、稀释倍数与安全间隔期——这些必须由当地登记与产品标签决定。
   口径沿用的是 `GuardrailService` 的**软约束**那条（命中药剂词须带"需人工确认"），
   而不是硬拒那条：推演没有引用可依，硬拒会把整段有依据的方案一起丢掉。
4. **参考基线必须标注它不采用用户输入**。见下。

### 参考基线：一份"不采用你输入"的数值

推演结果旁边并排展示机理模型的数值，但那份数值**来自固定标准情景**
（`PerformanceEvaluationService` 的初始条件是写死的），**不采用用户的农情输入**。
因此它随结果一起下发时固定带 `scopeNote`，界面上紧贴数值展示。

**实测还补了一条 `windowNote`**：60 天窗口下利润会算出 **-1447.70 元**——番茄坐果在推演后段才发生，
短窗口里产量没上来而资源成本已计满。数字没错，但含义是"窗口太短"而不是"经营亏损"。
既有的 `ProductionReportService` 只对"零产量"做了提示，覆盖不到这种"有产量但利润为负"的中间地带。
不解释的话，看到那个负数的人只会得出一个反向结论。

### 刻意没做：个性化生长曲线

原打算用用户输入的温湿光驱动 `TomatoCropGrowthModel` 逐日推进，做出"你棚里会长成什么样"的曲线。
**复核后放弃**，理由是它必然产出假曲线，且**不报错**：

- 缺光照时 `dW = 0`，但 GDD 照常累积、生育期照常推进、单果重照常增长、LAI 因衰老项衰减——
  输出是"生育期已到果实膨大期、单果重在长、全株干重零增长"，物理上已死却看起来像模型算出来的结论；
- 单点读数无法驱动逐日推进（用户填"中午 800 PPFD"按常量灌一整天，等于把夜间也算成 800）；
- `initial()` 是**幼苗**状态，用户棚早已在坐果期，没有任何输入能把状态设到对应位置。

拿假输入换来的"个性化"不是个性化，是把未知伪装成已知。要用这条路径，
前提是用户能提供**逐日气象序列 + 定植日期**，那时再作为"进阶模式"加回来。

### 两条通道的评测数字必须分开报告

推演通道不做检索，因此**不影响也不参与**检索准确性那组指标（`RetrievalEvalTest`、
`DeveloperHoldoutEvalTest`）。把两条通道的回答质量数字合起来引用是没有意义的——
它们的可信度来源完全不同：一条能追到编号与原文，另一条是模型的记忆。
