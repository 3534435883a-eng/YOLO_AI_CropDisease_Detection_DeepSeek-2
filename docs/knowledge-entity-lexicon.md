# 作物实体别名词典：来源、证据与实测效果

> 2026-09-23。本文记录"别名归一化"这件事**依据什么、效果多大**，以及哪些做法被测量否定。

## 一、为什么要做（实测缺陷）

知识库块内容与检索的作物过滤都使用**规范作物名**（如"马铃薯"），而农户口语常用别名（如"土豆"）。
实测两种真实场景的后果：

| 场景 | 修复前 | 说明 |
|---|---|---|
| **B. 调用方把作物写成别名**（crop="土豆"） | **零召回 2/2** | 过滤条件是 `chunkCrop.contains(cropType)`，`"马铃薯".contains("土豆")` 为假 → 全部命中被过滤掉 → 智能体只能拒答 |
| **A. 不给作物上下文、问题里用别名** | Top-1 40% / Top-3 60% | 只能靠症状词碰运气，块头部"作物：马铃薯"完全没被利用 |

（注：若给别名问题**同时传规范作物名**，过滤会替我们完成匹配，测出来是"100% 通过"的假象——首版评测就犯了这个错，已改为只测上面两种真实场景。）

## 二、词典来源与逐条证据

词典唯一数据源：`SpringBoot/src/main/resources/knowledge/crop-aliases.json`。
**来源性质：人工整理的通用农艺术语别称，非权威来源。** 每条都标注该别名是否在知识库原文中出现过：

| 规范作物 | 别名 | 库内证据 |
|---|---|---|
| 小麦 | 冬小麦、麦子、春小麦 | 冬小麦×5（库内原文出现） |
| 水稻 | 稻子、稻谷 | 稻谷×21（库内原文出现） |
| 苹果 | 苹果树 | 苹果树×7（库内原文出现） |
| 葡萄 | 葡萄树、提子 | 葡萄树×1（库内原文出现） |
| 番茄 | 西红柿、洋柿子、蕃茄、火柿子 | **该别名在知识库原文中 0 次出现** |
| 马铃薯 | 土豆、洋芋、薯仔、山药蛋 | **0 次出现** |
| 玉米 | 苞米、棒子、包谷、玉蜀黍 | **0 次出现** |
| 草莓 | 士多啤梨 | **0 次出现** |
| 棉花 | （不收录别名） | "棉花"本身即规范名（库内×24）；单字"棉"会在任意含该字的文本中误匹配，故不收录 |

测量脚本：对 `cropdisease.disease` 全部 100 条的症状/诱因/防治原文做正则计数，结果见下表（原始测量输出已归档）。

## 三、实测效果（真实语料 100 条 / 338 块，BM25+向量+RRF）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 别名提问 Top-1 | 40.0% | **80.0%** |
| 别名提问 Top-3 | 60.0% | **100.0%** |
| 场景 B 零召回 | 2/2 | **0/2** |

**无回归**（同一轮评测）：症状前缀 Top-1 95% / Top-3 100%、症状中段 Top-3 100%、负样本拒答 100%、

## 四、被测量否定的做法（记录以免重犯）

1. **用"知识图谱投影"替代**：把 `crop_type`/`disease_name`/`field_type` 这些**现有列**重新投影成
   节点与边，并不增加任何能力——"某作物有哪些病害""某病害完整档案"直接用 `SELECT DISTINCT … WHERE` 即可得到。
2. **抽"病害—病原"关系**：本以为知识库诱因文本里有拉丁学名，**实测 0 条**（100 条记录中无一含属种双名），不可行。
3. **抽"病害—药剂"关系**：防治文本药剂关键词覆盖 94/100（95%）、稀释倍数 79/100（80%）、剂型剂量 58/100（59%），
   覆盖面足够；但抽样即发现质量问题（如"1 000倍液"被截成"000倍液"、有效成分名会把前文一起吞进来）。
   **用抽取错误去生成"知识"风险高于收益，故不做**；药剂信息仍由检索直接返回带出处的原文片段。
4. **单字别名**：如"棉"——在任意含该字的文本中都会命中，作为别名会引入错误匹配。

## 五、工程教训（与知识库无关，但值得记录）

- **多构造器必须显式 `@Autowired`**：给 `KnowledgeRetriever` 增加第二个构造器后，Spring 找不到无参构造器，
  应用**整体启动失败**（报 `No default constructor found`）。
- **改构造器后必须跑全量测试**：本次只跑了 `RetrievalEvalTest`（不加载 Spring 上下文）就认为通过，
  漏掉了启动失败；只有 `EceTests`（`@SpringBootTest` 全上下文加载）能抓住这类问题。
- **PowerShell 管道会破坏中文 SQL**：`Get-Content -Raw | mysql` 会把中文按控制台编码重编码，
  实测"苹果"被写成"鑻规灉"。必须用 `cmd /c "... < 文件"` 让 mysql 直接读原始字节。
