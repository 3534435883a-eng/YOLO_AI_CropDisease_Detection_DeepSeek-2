# 禾序：成果展示、导出文件与关键代码说明

整理日期：2026-10-09。用途：队友撰写计划书、制作PPT、组织答辩和定位代码。项目名称保持“禾序：农业智能体决策与番茄温室仿真平台”。

本文件以当前代码及10月9日保留的验证材料为依据。此次仅交付这一份综合说明，原始报告、数据和素材通过链接访问。

## 一、项目成果怎样讲清楚

可以用这段话介绍：

> 禾序面向基层农业工作者，将农情描述、病害图像识别、农业知识检索、大模型决策和番茄大棚状态管理连接起来。用户提出问题或上传农情后，助手结合当前大棚和资料给出管理方案，平台展示设备动作对温湿度、根区、风险条件及资源投入的影响，并通过新观测修正生长预测、通过复查跟进管理效果，最终形成可追溯的农情报告。

展示围绕一个具体问题展开：**“番茄连续阴雨、叶片有斑，接下来怎样管理？”**

| 成果 | 用户获得什么 | 展示证据 |
| --- | --- | --- |
| 农情任务贯通 | 图片、CSV、问答、行动与复查沿用同一问题，跨页可以继续 | 大棚右侧同一农情任务；导出报告 |
| 智能诊断与决策 | 图像给候选，助手核对病因线索、资料和环境，提出具体措施 | 检测框、候选结果、回答及引用 |
| 大棚作用可见 | 能看到设备状态、温湿度、根区水量、冠层湿润条件和水电代价 | 三维设备动画、作用说明、未干预对照 |
| 预测持续修正 | 新观测到达后更新生长状态，继续产生下一时段预测 | 模型校准页曲线、观测点和更新事件 |
| 服务结果可留存 | 能查当时依据、参数、建议、平台应用与人工复查 | Markdown报告、JSON运行记录、参数指纹 |

视觉识别、普通问答、文献库仍可独立使用；深入的管理流程以番茄大棚为主线。

## 二、默认展示背景与回答口径

**默认以当前大棚状态作为演示场景内的管理事实。** 正常问答直接描述当前棚温、湿度、事件、根区状态和措施作用，不反复加“根据虚拟数据”“在仿真中”等前缀。

存在 `current.scenario.environment` 时，它是事件和设备作用后的当前管理状态；`current.environment` 是回放参考输入，不混成同一个状态。来源、模型假设和真实设备接入情况集中放在技术说明或折叠的来源区域，用户主动询问时如实解释。

适合展示的回答示例（说明文案，不是新一轮模型实测输出）：

> 当前棚内湿度偏高，先核查叶片正反面和新增病斑。建议结合外界条件安排通风与环流，并复查叶面是否干燥；设备方案应用后，继续观察棚温、湿度、根区和耗电变化。如果处理后湿度没有下降，应调整方案，不能把设备开启当作管理成功。

“建议执行”“正在处理”“方案已应用”仍以平台回执区分。识别候选不直接写成确诊，已有病斑不会因为环境指标变好就自动消失。用户询问是否已经控制现场设备时，按实际接入情况回答。

本次已调整关联问答、设备AI和关联规划的提示；关联规划取消固定的非实测声明横幅，助手侧栏来源说明改为折叠入口。新口径用于后续生成，历史回答和导出档案保留原内容。

## 三、答辩展示顺序

推荐约5–7分钟，所有操作尽量围绕同一农情任务。此处是操作讲解安排，不新增录像。

| 顺序 | 页面与操作 | 重点讲什么 |
| --- | --- | --- |
| 1. 提出问题 | [番茄大棚](http://localhost:8100/index.html#/digitalTwin)：输入阴雨、叶斑问题，建立任务 | 平台围绕具体农情提供决策服务 |
| 2. 补充依据 | 同任务“农情证据”：上传病叶图和CSV，核对字段 | 图像提供候选；农情输入有来源、时间与缺失信息 |
| 3. 助手研判 | 大棚助手或[决策助手](http://localhost:8100/index.html#/agentChat)：解释问题、形成措施 | 大模型能解释原理，必要时查资料，引用服务于具体结论 |
| 4. 应用与观察 | 大棚事件和设备面板；可展示自动接管 | 事件改变环境，方案经过设备约束，动作影响状态 |
| 5. 比较效果 | 大棚作用说明和对照指标 | 同事件下比较处理与未干预分支，并看水、电和风险条件 |
| 6. 解释修正 | [模型校准](http://localhost:8100/index.html#/modelCalibration)：曲线、观测点、更新记录 | 先预测、再接收观测、计算偏差并更新状态；说明下一次预测 |
| 7. 管理跟进 | [农事规划](http://localhost:8100/index.html#/agentSimulation)：按请求天数生成清单；行动与复查 | 环境设备和人工病叶处理各自有事项、代价和复查条件 |
| 8. 导出结果 | 大棚“导出报告”；[文献库](http://localhost:8100/index.html#/referenceLibrary)核对资料 | 报告把问题、依据、方案、反馈和复查连在一起 |

自动接管会生成新事件并请求AI，现场展示时保留暂停、继续和人工观察的节奏。性能或模型效果的数字，使用对应运行的导出结果，不直接从旧截图抄数。

## 四、平台能导出什么

| 文件 | 网页入口 | 格式与命名 | 适合用途 |
| --- | --- | --- | --- |
| 统一农情报告 | 大棚农情面板“导出报告” | Markdown；`农情管理报告-任务前8位.md` | 计划书案例、完整管理过程及追溯 |
| 单次农事规划 | 规划完成后的“导出报告”或历史记录 | Markdown；`agri-plan-记录ID.md` | 某次方案的人工事项、日程和管理建议 |
| 在线已接入数据 | 模型校准完整工作区“导出已接入数据” | JSON；`m3-online-年份-游标.json` | 当前运行、已加载帧、事件、指标、来源及版本核查 |
| 历史参数校准 | 模型校准页“导出历史校准” | JSON；`参数版本.json` | 参数、训练/保留年份及历史评价 |
| 农情列名模板 | 规划页农情上传区域“下载列名模板” | CSV | 准备可核对的农情字段；这是输入模板 |
| 本地文献原文 | 文献库对应资料入口 | 原PDF或登记来源链接 | 论文、标准与引用核对 |

统一报告包含问题、证据、建议、人工行动、设备回执、对照变化、资源、复查、引用和冻结参数附录。该报告按同一任务导出，不从另一运行补效果。

当前正式报告下载主要为Markdown，数值和运行资料主要为JSON；PPT可使用报告正文、图表与截图。网页的“已接入数据”导出是分析资料，服务端恢复包还保存滤波和作物状态，二者用途不同。

## 七、适合讲解的三个算法片段

### 7.1 生长预测：积温推进节间伸长

每半小时根据温度增加有效积温：

```java
double gdd = Math.max(0, t - TomatoGrowthParameters.BASE_TEMPERATURE_C) / 48;
for (Plant p : r.plants) {
    p.openAge += gdd;
    p.filter.predict(gdd, 1.0 / 48, env.path("estimated").asBoolean());
}
```

节位按间隔依次产生，每个节间按平滑的伸长曲线累加得到株高。输入是热龄，输出是株高；这是简化机制模型，不是对完整作物三维生理过程的逐项复现。

### 7.2 观测修正：扩展卡尔曼滤波更新有效热龄

核心计算来自 `OnlineInternodeFilter.update`：

```java
double s = d*d*variance + MEASUREMENT_VARIANCE_CM2;
double gain = variance*d/s;
double innovation = observed-before;
double nextAge = Math.max(0, age+gain*innovation);
double nextVariance = (1-gain*d)*(1-gain*d)*variance
        + gain*gain*MEASUREMENT_VARIANCE_CM2;
```

`innovation`是“观测株高减观测前预测”；`d`是株高对热龄的导数；`gain`把偏差转换为热龄修正。模型参数在当前运行冻结，修正的是状态，不是每来一个观测就重新拟合全部参数。观测噪声和过程不确定性仍有工程设定，需要数据验证。

展示时分别看三项：固定参数模拟误差、在线更新前预测误差、更新后拟合偏差。更新后更贴近刚收到的观测，不等于对下一次观测的预测已经同样准确。

### 7.3 管理反馈：设备改变环境，再计算水量与风险条件

根区储水的核对关系：

```text
根区水量变化 = 滴灌补水 − 蒸散 − 排水
灌溉量(L) = 流量(L/min) × 出力 × 模拟分钟
电量(kWh) = 功率(kW) × 出力 × 模拟分钟 / 60
```

这是讲解关系式，完整实现还包含饱和溢出、排水时间常数、分钟积分和非负约束。当前参考面积252m²、有效储水层0.25m，对应63000L根层体积；它们是当前场景的工程参数，不应直接换成任意实际棚的灌溉处方。

设备对温湿度的作用经场景模型推进，根区变化影响水分胁迫；高湿和叶面湿润代理形成复查提示。风险条件提示不直接计算病斑面积或治愈率。

## 八、两个反馈过程的价值

**观测驱动的预测反馈：** 机制模型持续预测，新观测到达后计算偏差，根据不确定性递推更新生长状态，再进入下一段预测。价值是把固定模型变为能够随观测修正的状态估计过程；用后续观测前误差检验它是否有效。

**行动驱动的管理反馈：** 当前事件与农情触发研判，AI提出措施，平台核查设备约束后应用，计算环境、根区与资源变化，再与同事件未干预分支比较，结合人工复查继续调整。价值是让管理建议有作用机制、执行状态、效果与代价，而不是只生成一段回答。

两者在同一大棚任务中衔接：一个修正“对状态的认识”，一个复核“措施带来的变化”。株高预测改善不能单独证明设备响应、病害控制或现场增产有效。
