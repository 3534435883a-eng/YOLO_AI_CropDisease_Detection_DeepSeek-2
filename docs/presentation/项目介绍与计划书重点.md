# 禾序：农业智能体决策与番茄温室仿真验证平台

整理日期：2026-10-05。以下内容依据当前项目代码、已导入数据及本次网页实操，适合队友编写计划书、制作 PPT。名称可按团队最终报名名称调整。

## 一、可直接使用的项目摘要

本项目面向设施农业种植户、农技人员和教学演示场景，构建集病害视觉识别、农业知识检索、大模型决策、番茄生长预测和温室场景推演于一体的农业智能体平台。系统接收作物图像、视频及文字农情，通过 YOLO 模型形成候选病害信号，结合农业资料与 DeepSeek 大模型提供解释和管理建议；在番茄数字温室中构建机理模型与观测数据融合的在线预测机制，模拟环境数据持续接入和生长观测逐次到达，通过数据同化更新作物状态，使预测随新增信息动态修正。同时，平台可自动生成天气扰动、分析环境风险、请求 AI 处置方案，并在虚拟设备和环境模型中观察执行反馈。项目形成“农情感知—状态预测—风险研判—仿真处置—反馈修正”的工作流程，为农业决策服务的研究、教学与后续现场应用提供可追溯的软件原型。现阶段使用 Horti-M3 公开历史数据按时间顺序回放，模拟在线观测接入过程。

## 二、项目要解决的问题

1. **农情信息分散。** 叶片照片、环境读数、栽培经验和论文资料分属不同渠道，使用者难以形成完整判断。
2. **建议需要依据。** 相同症状可能有不同原因，模型识别结果需要结合症状、环境与资料复核；专业建议也需要可查出处。
3. **方案效果难提前观察。** 通风、湿帘、加热等设备会同时影响温湿度，单项操作可能改善一个指标、恶化另一个指标。
4. **预测会发生偏离。** 固定参数模型受品种、批次和环境影响，需要随新观测到达更新状态，并保留可检验的误差指标。

项目价值在于把上述信息组织进连续决策过程，使用户能看到“为什么这样判断、准备做什么、执行后发生了什么、预测怎样被新数据修正”。实际节省时间、减产预防和经济收益仍需现场试验与用户调研验证。

## 三、建议贯穿计划书的工作主线

**农情输入 → 视觉观察与环境状态 → 知识检索和大模型解释 → 风险与方案 → 受约束仿真执行 → 反馈与复盘。**

| 环节 | 当前实现 | 与下一环节的关系 |
|---|---|---|
| 观察 | 图像、视频检测，文字或表单农情输入，M3 历史记录按时间回放 | 为研判提供候选信号和当前状态 |
| 研判 | 病害名称映射、资料检索、引用证据、普通及大棚关联问答 | 解释问题与证据边界 |
| 预测 | 温度驱动的节间出现与伸长机制、株高预测、环境风险累计 | 帮助观察生长偏差和风险持续过程 |
| 决策 | 农事规划、随机事件下的 AI 设备方案、服务端动作约束 | 把解释转化为可观察的目标和日程 |
| 验证 | 三维温室、虚拟设备状态、同事件未干预对照、执行过程记录 | 检查方案是否应用及环境反馈 |
| 修正 | 接收新株高观测，通过数据同化递推更新生长状态及其不确定性 | 从修正后的状态继续预测，保留观测前误差供评价 |

图像识别、农事规划和大棚推演有各自入口。当前已验证识别结果可带入助手，大棚运行编号可带入关联问答及校准工作区；完整农事规划尚未作为同一 M3 运行的自动设备调度计划。计划书应按这些实际连接关系绘图。

## 四、六个重点功能

### 1. 多作物病害观察

项目包含番茄、马铃薯、苹果、葡萄、草莓、玉米、水稻、小麦、棉花九个作物检测模型，提供图像、视频和摄像入口。输出框、类别与置信度，并保留记录供复核。温室生长与控制展示当前集中在番茄。

模型置信度表示一次预测的评分；它不能直接写成识别准确率。当前覆盖页面列出 50 个非健康类别，其中 25 个已有可核对的病害库映射，25 个仍待完善。其他相关知识的检索能力与此名称映射覆盖率是不同指标。

### 2. 有证据，也能独立交流的决策助手

普通问答用于独立的栽培、原理和资料问题；关联问答读取指定大棚运行的环境、事件、设备和反馈。两类会话分别保留。需要农业资料时检索并提供编号引用；一般解释可以直接由模型回答。本次实操已验证两类回答路径。

当前检索采用 BM25、BGE 中文向量和 RRF 排名融合，知识库状态显示 41 项登记来源、495 个文本块及对应向量。文献库另有 85 份本地 PDF；本地存档和进入检索的文本片段分别管理。

### 3. 能说明依据的番茄生长预测

株高机制以有效积温作为生长时间尺度，按节间出现间隔累计节间，并用 Logistic 曲线表示节间伸长。模型输出连续曲线，实测日期提供离散检查点。它是项目的简化机制实现，尚未完整复现论文中的作物模型。

其他生长、物候和设备响应量中包含工程假设。当前株高结果不能证明产量、果实饱满度或真实设备效率已经准确。

### 4. 基于数据同化的在线预测修正

针对设施农业中观测频率不一致、生长测量稀疏和模型状态随时间偏离的问题，平台构建“机理预测—观测接入—状态同化—递推预测”的在线修正机制。环境数据按时间进入生长模型，新株高观测到达时与此前预测进行对照，系统结合模型状态不确定性与观测噪声估计，动态确定修正幅度，并从更新后的状态继续推演，使观测信息影响后续生长轨迹。

当前实现以有效积温驱动节间出现和 Logistic 伸长，将有效热龄作为待估计状态，采用一维扩展卡尔曼滤波进行非线性观测同化。没有新株高测量时，模型持续预测并传播状态不确定性；含估计输入的时段提高过程噪声，反映输入可信度差异。更新记录保留预测值、观测值、修正值、观测权重与来源，为偏差分析和答辩展示提供可追溯依据。

现阶段以 Horti-M3 历史数据顺序回放模拟在线采集：系统在对应模拟时刻消费观测，未来株高不提前参与当下更新。基础参数预先使用 2023、2024 年同品种 CK 数据标定并固定，2025 年用于保留年份评价和在线回放；其首日株高用于初始化，后续株高不参与基础参数拟合。在线修正更新生长状态，后续可沿用该计算流程接入现场传感器与人工表型观测。

评价分别报告新观测到达前的预测误差和吸收观测后的拟合偏差。当前已实现株高状态修正，产量、果实品质和设备响应的观测同化与现场验证列入后续研究。

### 5. 随机事件下的 AI 仿真接管

温室可生成暴雨、降温、热浪、强风、连续阴雨、夜间高湿及设备故障事件。系统读取当前场景，请求 AI 形成设备目标，再由服务端约束核查，并在仿真中应用、观察后续环境。

三维界面展示植株、设备及测点，支持视角切换、设备定位、详情和动画。自动接管已通过实操。聊天中直接请求执行的授权传递仍需修正，不能把模型声称“执行”当作执行成功；应以服务端应用状态和设备回执为准。

### 6. 农事规划与资料追溯

农事规划支持表单、自然语言和 CSV 入口，可生成动作清单、日程、风险提示并保存历史，报告目前导出为 Markdown。文字解析草稿显示字段及原话依据，供用户核对。文献与来源页面用于查找 PDF、来源版本、许可说明和原文链接；采购库存则承担独立台账功能。

## 五、观测同化与决策执行的闭环验证机制

项目围绕“预测能否接受观测检验、方案能否接受执行检验”构建两个相互衔接的反馈过程，将生长状态估计、风险研判与仿真处置纳入可追溯的验证流程。

**生长预测闭环：以新增观测约束后续预测。** 环境数据持续驱动机理模型推演，生长观测按对应时刻进入系统。新株高测量到达后，系统计算观测与预测之间的偏差，通过扩展卡尔曼滤波，依据状态不确定性与观测噪声估计修正有效热龄，再从更新后的状态继续预测。该过程将离散表型测量转化为对后续生长轨迹的持续约束；效果通过下一次观测到达前的预测误差评价，并单独记录更新后的拟合偏差。现阶段采用 M3 历史观测顺序回放，模拟在线数据持续接入。

**决策执行闭环：以仿真反馈检验处置方案。** 天气扰动或设备故障触发风险研判，AI 结合当前环境与设备状态生成处置方案，经服务端约束核查后应用于虚拟设备。系统持续记录温湿度变化、设备状态与风险表现，并与同一事件条件下的未干预分支对照，为后续复核和方案调整提供反馈。该过程使管理建议具有可观察的执行结果，能够呈现降温、增湿等同时发生的影响及其取舍。

两个闭环分别承担生长状态修正和处置效果验证，在同一温室场景中共同支撑“状态预测—风险研判—仿真执行—反馈复核”的决策流程。评价按对象分别开展：株高预测采用观测前误差，设备处置采用同事件仿真对照与风险变化。当前证据覆盖株高状态更新和模拟环境反馈，现场设备响应与实际生产效益将在后续接入真实观测后验证。

## 六、数据来源与当前证据

Horti-M3-Tomato 覆盖 2023—2025 三个生长季，采集地点为哈尔滨的黑龙江省农业科学院园艺分院温室，包含半小时环境记录、影像和人工表型等数据。数据论文由 Yu Gong 等发表于 *Scientific Data*（2026）。我们使用公开数据进行导入、回放与模型校验，数据采集由原研究团队完成。[原始数据论文](https://www.nature.com/articles/s41597-026-07074-w)，[公开数据记录](https://zenodo.org/records/17217565)。

项目导入概况为 2484 条株高记录、跨年份 26 个测量日期；本次展示选择 2025 / 广辉201 / CK 子集，株高有 8 个测量日期。人工株高测量频率与半小时环境采样频率不同。

| 本次实际看到的证据 | 数值或表现 | 合适的表述范围 |
|---|---|---|
| 番茄图像样例 | 早疫病候选评分 85.64%，页面用时 0.899 秒 | 一个样例的识别结果，不是总体精度 |
| 独立问答 | 原理解释约 6.8 秒，未强制引用资料 | 一次功能与耗时观察，不是服务性能基准 |
| 七天规划 | 完整方案约 52.9 秒，含动作、日程和历史记录 | 一次实际生成结果 |
| 2025 保留年份株高 | 原模拟 RMSE 111.92 cm，校准后 22.77 cm，42 个配对点 | 所选批次、相对原模拟误差降低 79.7% |
| 2024 株高对照 | 31.73 → 46.53 cm | 该年变差，应保留以分析泛化限制 |
| 在线回放至 05-11 | 12 个观测配对；固定参数 RMSE 4.98、在线观测前预测 4.19、更新后拟合偏差 1.09 cm | 当前短区间结果；拟合偏差不是独立预测精度 |
| 连续阴雨仿真反馈 | 某次干预相对同事件未干预温度 +2.6℃、湿度 −14 个百分点 | 模型分支差异，不是现场实测节能或增产效果 |

统计来自本次页面及保留截图。正式提交前建议增加独立识别验证、问答证据正确性评估、更多批次及完整生长季测试。

## 七、计划书最值得突出的亮点

1. **连续的决策服务流程：** 图像候选、资料证据、环境状态、风险与仿真反馈在平台内衔接。
2. **可查证的智能体：** 回答有工具记录与引用出处，数据有历史、估计、模型和仿真的区分。
3. **机理与观测融合的在线预测：** 将温度驱动的生长机制与非线性状态估计结合，在观测稀疏、采样频率不一致的条件下持续预测并递推修正；通过观测前误差、更新后状态和来源记录说明修正过程。
4. **可观察的处置结果：** 将 AI 方案置于设备约束和环境模型中，与未干预分支对照。
5. **围绕番茄形成可讲清的场景：** 多作物识别提供入口，番茄温室承担深入的生长、风险和决策展示。

创新贡献可表述为农业场景下的系统集成、数据组织、交互与验证流程设计。YOLO、RAG、Logistic 和卡尔曼滤波是已有方法，不应写成团队原创算法。

## 十、提交材料时的统一口径

当前成果是有实际模型和大模型调用的农业决策软件原型，温室控制发生在仿真场景。M3 在演示中按时间回放，不能称为本团队正在实时采集；随机天气、缺测补值、设备效果与模型生长量均应保留相应标注。真实温室控制、稳定增产节能和经济收益属于后续验证目标。
